# Проверки переноса — 5 ноября 2026

Версия 0.1.1: сборка на Ubuntu 18.04 amd64, GCC 8.4 с -m32, C++17,
CMake 3.31.6. OpenSSL 3.5.9 LTS собран из официального проверенного архива
как статическая x86-библиотека (no-shared/no-module/no-pinshared).
Плагин: ELF32 Intel 80386; старшая фактически импортированная GLIBC — 2.25,
поддерживаемая и проверенная сборочная база — glibc 2.27. Динамические зависимости:
libc.so.6, libm.so.6, libpthread.so.0, libdl.so.2, librt.so.1, ld-linux.so.2.
MySQL, OpenSSL, zlib и C++ runtime встроены; внешних GLIBCXX/CXXABI нет.

Новая сборка 0.1.1 проверена:

- Три CTest в Ubuntu 18.04/glibc 2.27: city_rules, city_events,
  city_plugin_load. Последний делает dlopen(RTLD_NOW), проверяет экспортируемые
  callbacks и dlclose: это фактическая проверка старого загрузчика.
- Полный DatabaseTest с MariaDB 10.11 и новым OpenSSL в старой среде: вход,
  выплата, сохранение, организации, покупка квартир и ограничение очереди прошли.
- Семь ElfCompatibilityTest: упаковка отклоняет GLIBC_2.33/2.34, GLIBC_PRIVATE,
  внешний C++ runtime, неверную архитектуру и неожиданные внешние библиотеки.
- open.mp 1.6.7.3218: загрузка новой .so, инициализация режима, MySQL,
  UDP info и штатная остановка через обработчик VPS прошли на современном QEMU.
- Контрольные суммы файлов и содержимого архивов проверяются после упаковки.

Ниже — дополнительные проверки первого переноса (0.1.0, 2 ноября); его бинарный
плагин glibc 2.34 заменён в 0.1.1 из-за реальной ошибки загрузки RideHost.

- Исходники из готового ZIP распакованы в отдельный каталог: чистая сборка
  citylive.so и оба CTest прошли без обращения к исходному рабочему каталогу.
- CTest city_rules: имена, пределы чата, CP1251, позиции, условия доставки,
  этажи/двери и проходной балл собеседований.
- CTest city_events с _GLIBCXX_DEBUG: удаление получателя восьми событий и
  обратный порядок жизни диспетчера/получателя. Это покрывает исправление
  ошибочной итерации по изменяемому вектору в исходном samp-cpp.
- Реальная MariaDB 10.11 в отдельном контейнере без открытых сетевых портов:
  регистрация, дубликат, неверный/верный пароль, работа и выплата, сохранение
  позиции, собеседование, недостаток денег, покупка жилья, два покупателя
  одной квартиры, сохранение владельца после входа, ограничение очереди.
- Официальный open.mp 1.6.7.3218 в отдельной локальной сети: загрузка citylive.so,
  инициализация C++ режима и MySQL, ответ на UDP SA-MP info, пять завершений через
  команду exit; ещё три завершения по сигналу через supervise-vps.py.
- DeployScriptsTest.py: сохранение порта, bind, maxplayers и RCON-пароля,
  предварительный просмотр, резервные копии, отказ перезаписать backup.
- Архивы: контрольные суммы каждого файла, i386/AMX, обязательные файлы,
  отсутствие рабочей database.ini и серверного исполняемого файла.

Прямой SIGINT при работе open.mp через QEMU оказался нестабилен: чистый сервер
без нашего плагина тоже не завершился в контрольный срок. Для VPS подготовлен
обработчик, переводящий systemctl stop / Ctrl+C в команду exit по stdin.

Это не нагрузочный тест на 50–100 человек. Реальный вход с PC/Android-клиента,
графическое расположение входов/NPC, поездки, интерьер и TextDraw на телефоне
ещё не проверены. Нативный VPS и RideHost не использовались для этих проверок.

Тест БД требует специально выделенной пустой базы; не запускать DatabaseTest
на рабочей базе. Её конфигурация и тестовые пароли в исходники/архивы не включены.
Официальный open.mp для локальной проверки также не включён в репозиторий.

Старый QEMU 2.11 из Ubuntu 18.04 успешно выполнил CTest и DatabaseTest, но отказал
в запуске самого omp-server с «Operation not permitted» в текущем контейнере.
Поэтому полная проверка open.mp для 0.1.1 использует современный QEMU из среды
Ubuntu 22.04; совместимость плагина со старым загрузчиком проверена отдельно выше.
Точный релиз glibc RideHost из его журнала не известен; загрузка нового файла
на самом хостинге здесь не выполнялась.
