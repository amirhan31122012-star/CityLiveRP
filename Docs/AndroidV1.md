# Тестовый APK CityLive RP V1

Это локальная сборка ARM64 с текстурами ASTC для личного тестирования.
BuildAndroidV1.cmd собирает Development; BuildAndroidV1Shipping.cmd — Shipping
для сравнения производительности без диагностических проверок Development.
Данные упакованы внутрь APK, публикация в магазине не выполняется.
Нужен Android-телефон с ARM64 и поддержкой ASTC/OpenGL ES 3.2.

1. Обновите проект в GitHub Desktop и запустите ImportPoliceDistrict.cmd.
   Он установит новую основную карту. Проверьте город через BuildAndOpen.cmd.
2. В Unreal откройте «Правка → Настройки проекта → Платформы → Android».
   Если требуется настройка проекта для Android, нажмите соответствующую кнопку.
   Примите лицензию Android SDK, если редактор предлагает это действие.
3. Через меню «Платформы → Android» проверьте состояние SDK. Если он не установлен,
   используйте предложенную Unreal установку SDK/Turnkey. Названия пунктов могут
   отличаться в переводе UE. Версии SDK/NDK выбирайте по требованиям установленного UE.
4. Закройте редактор. Откройте BuildAndroidV1.cmd двойным щелчком.
5. При успехе откроется Releases/AndroidV1. Найдите APK внутри созданных подпапок.
6. Скопируйте APK на телефон, откройте его и разрешите установку из этого источника,
   если Android запросит. Это тестовая версия вне магазина.

Если проверка SDK не проходит — пришлите Saved/VerifyAndroidSDK.log. Если не проходит сама сборка —
Saved/BuildAndroidV1.log. Сборка Windows не проверяет наличие Android SDK.

Проверьте на телефоне: запуск, цвет персонажа, джойстик, свайп камеры одновременно
с газом, тормоз/задний ход, четыре места, двери и поездку по району в течение 10 минут.
Зафиксируйте модель телефона, частоту кадров, нагрев и вылеты. Проект ещё не прошёл
проверку Android; готовность V1 определяется этим тестом, а не наличием скрипта.

Перед распространением другим людям добавьте в игру раздел авторов с данными из
Docs/CharacterCredits.md и проверьте условия Fab-пакета автомобилей. Текущий APK
не содержит отдельного экрана авторов. Для магазина потребуется отдельная подпись.

Сборка выбирает карту по Saved/ModernCityMap.txt, записанному успешным импортом.
Перед упаковкой проверяет существование карты и персонажа и восстанавливает
GameDefaultMap/EditorStartupMap на этот город в локальном DefaultEngine.ini.
Новая карта после каждого импорта получает номер Run; путь не задаётся вручную.
Старая площадка CityLive_V1 больше не включена в MapsToCook. Производная модель
автомобиля из CityLiveVehicles включается в упаковку для динамической загрузки.
Каждая сборка сохраняется в отдельную подпапку Releases/AndroidV1/<номер>, чтобы
невозможно было принять APK предыдущей сборки за новый. Исходники города повторно
не обрабатываются. Статические припаркованные машины набора не являются игровыми.

Скрипт проверен статически; Windows/UAT/Android SDK отсутствуют в облачной среде.
Фактическая сборка и производительность на телефоне ещё не проверены.

Значок игры: огненный тигр из Assets/Branding/CityLiveTiger.png. Legacy и adaptive
ресурсы подключены в Build/Android/res; вводить путь в настройках Unreal не нужно.
После обновления проекта и закрытия редактора запускайте BuildAndroidV1.cmd.
Карту повторно импортировать не нужно. Результат появится в новой подпапке
Releases/AndroidV1; APK переносится на телефон вместе со всем игровым содержимым
внутри файла. Значок и adaptive-маску нужно проверить после установки на устройстве.

Если открытие большой карты мешает настройке SDK, используйте
OpenAndroidSettings.cmd вместо BuildAndOpen.cmd. Редактор запускается с пустым
уровнем /Engine/Maps/Entry, город не загружается. Затем откройте «Правка →
Настройки проекта → Платформы → Android SDK». Скрипт не компилирует C++ и не
меняет EditorStartupMap, GameDefaultMap, сохранённую карту или marker для APK.
Для проверки игры используйте обычный BuildAndOpen.cmd. Для упаковки после
настройки SDK закройте редактор и запустите BuildAndroidV1.cmd.

Путь SDK должен совпадать с Android SDK Location в Android Studio. В последнем
скриншоте пользователя SDK установлен в C:\Users\amir1\AppData\Local — это
допустимый нестандартный корень. Тогда NDK r27c находится в
C:\Users\amir1\AppData\Local\ndk\27.2.12479018. Не приписывайте Android\Sdk
к этому пути без переноса/установки туда пакетов. Если фактический SDK Location
изменён, используйте новое значение. После установки Android-компонента UE
требуются и SDK/NDK: наличие компонента Launcher само по себе их не заменяет.

Текущая тестовая версия — 1.2.0-test (StoreVersion=5): перед сборкой
запустите ImportPoliceDistrict.cmd. Новая карта с полицией и дворами становится
основной вместо прежнего города. Плавающий джойстик, педали, персонаж и машина
сохраняются. RendererSettings не меняются. Полная инструкция: Docs/PoliceDistrict.md.
RestoreCityV1 / UpdateCityV11 и перенастройка SDK для этого обновления не нужны.

Изображения splashscreen_landscape / splashscreen_portrait в
Build/Android/res/drawable заменяют стандартные ресурсы UE. Заставка показывает
иллюстрацию города, не снимок действующей карты. Сначала на Android 12+ может
отображаться системный значок с тигром. Изменение заставки не устраняет
неизвестную причину вылета; для журнала используйте Docs/AndroidCrash.md.

## Сравнение производительности в Shipping

На снимке stat unit: Frame ~299 мс (около 3.3 FPS), Game ~23 мс, Draw/GPU ~37 мс.
Эти измерения не объясняют всю задержку кадра. На следующем снимке stat streaming
пул ~719 МБ при лимите 800 МБ, Required/Wanted ~82 МБ, Inflight Requests=0.
Переполнения и активной подгрузки в этот момент не видно. Это не исключает
нехватку общей RAM, другие виды загрузки, перегрев или задержки в иных кадрах.
Предупреждения PROFILING WITH AI LOGGING ON / GC VERIFY ON указывают на
проверки Development; сами предупреждения не доказывают причину тормозов.

Следующий отдельный эксперимент — Shipping с тем же содержимым и графикой:

1. Закройте Unreal, обновите ветку в GitHub Desktop.
2. Запустите BuildAndroidV1Shipping.cmd после успешного ImportPoliceDistrict.cmd.
3. Результат находится в Releases/AndroidV1/Shipping/<номер>. Файл BuildInfo.txt
   подтверждает Configuration=Shipping и карту. Установите APK из этой папки
   поверх игры; используйте тот же компьютер и прежний ключ подписи.
   For Distribution для этого сравнения включать не требуется.
4. Сравните ту же улицу: 30 секунд стоя на месте, затем ту же поездку.
   Температура телефона и фоновые приложения влияют на результат.

Конфигурация меняется только в аргументе UAT -clientconfig=Shipping.
RendererSettings, профили устройств, модели, текстуры, свет, тени, разрешение,
город и игровой код сохраняются при сравнении Development и Shipping одной версии.
Это сравнительная сборка, а не публикация в магазине. Консоль и команды stat
в обычной Shipping-сборке недоступны; диагностику Development можно снова
собрать прежним BuildAndroidV1.cmd. Выходные папки двух конфигураций разделены.

Лог Shipping: Saved/BuildAndroidV1Shipping.log. Первая сборка Shipping компилирует
другую конфигурацию и может занять долгое время. Скрипт проверен статически;
Unreal/Android в облаке отсутствуют, результат и прирост FPS не подтверждены.
Если задержки сохраняются, следующий шаг — замер на устройстве, затем LOD,
число материалов/отрисовок и геометрия карты. Shipping сам по себе не уменьшает
тяжёлые сетки и не гарантирует стабильную частоту кадров.
