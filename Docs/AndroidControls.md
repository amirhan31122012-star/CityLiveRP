# Управление CityLive RP для Android

## Управление

- Один джойстик слева: вверх/вниз — движение вперёд/назад относительно персонажа;
  вправо/влево — непрерывный поворот в эту сторону, включая поворот на месте.
  Длительное удержание даёт несколько полных оборотов, без ограничения угла.
  Максимальная скорость — 75 градусов в секунду. Начало поворота, смена стороны
  и остановка после отпускания сглажены. Полное прекращение вращения быстрое,
  но не мгновенное: максимальный остаточный доворот после отпускания — около 9,4°.
- Два нажатия на джойстик с интервалом до 0,3 секунды: присесть / встать.
- Кнопка с изображением бегущего человека справа: удерживать для ускорения, отпустить для обычной скорости.
- Два нажатия на кнопку бега с интервалом до 0,3 секунды: прыжок.
- Можно двигаться левым пальцем и управлять бегом/прыжком правым одновременно.
- Камера жёстко закреплена за спиной без отдельного запаздывания;
  плавно поворачивается сам персонаж вместе с камерой. Второго джойстика нет.
- При удержании кнопка бега мягко подсвечивается зелёным, при отпускании
  возвращается в обычное состояние. Подписи «БЕГ» на самой кнопке нет.

Управление создаётся в C++ контроллером CityLiveRPPlayerController. Стандартный
сенсорный интерфейс и виджет управления шаблона заменяются этим интерфейсом.
Не требуется создавать новый виджет Blueprint или менять двоичные ресурсы.
Механика приседания использует стандартный CharacterMovement (капсула и скорость).
Программная поза приседания добавлена поверх текущей анимации: сгибание ног,
опускание таза и наклон корпуса. Описание и проверки — в ProceduralCrouch.md.
Это локальное управление прототипа; сетевые механики в этой задаче не добавлялись.

## Проверка на Windows

1. Закрыть Unreal Editor перед обновлением исходников. В GitHub Desktop скачать
   изменения ветки feature/android-touch-controls.
2. Открыть папку репозитория через GitHub Desktop и запустить BuildAndOpen.cmd.
   Он собирает CityLiveRPEditor для Win64 через установленный UE 5.8 и открывает
   именно проект из своей папки только после успешной сборки. Достаточно двойного
   нажатия на файл: кроме реестра, проверяется стандартная папка установки
   C:\Program Files\Epic Games\UE_5.8. Если движок установлен в другом месте
   и не найден автоматически, можно указать папку движка аргументом.
   При ошибке сборки сохранить Saved/BuildCityLiveRP.log. Скрипт проверяет запущенный
   UnrealEditor.exe и не удаляет старые файлы или пользовательские изменения.
3. Открыть карту Content/ThirdPerson/Lvl_ThirdPerson и нажать «Играть».
4. Экранное управление включено и на компьютере; мышь имитирует одно касание.
   Нажимать и перемещать левый джойстик, затем проверить правую кнопку.
   Два пальца одновременно нужно проверять на сенсорном устройстве.

При запуске новой версии в журнале UE появляется «CityLive RP controls v4».
На правой кнопке должен быть силуэт бегущего человека, без текста «БЕГ».
Если текст остался, запущена другая сборка; изменение камеры в редакторе этого
не исправит. При проблеме сохранить также Saved/Logs/CityLiveRP.log.

Камера теперь рассчитывается в CalcCamera непосредственно относительно положения
и направления персонажа: 420 см позади, на 140 см выше точки взгляда. Она смотрит
на точку над центром капсулы. Поворот контроллера и смещения камер Blueprint не
задают итоговый вид. При столкновении с окружением камера приближается по лучу
к персонажу; в тесных местах полная видимость модели требует проверки на карте.

## Обязательная проверка на Android

- Пройти вперёд, назад и в стороны, резко развернуться на 180 градусов;
  камера должна оставаться за спиной, персонаж — в центре кадра.
- Проверить повороты возле стены: камера должна реагировать на препятствие.
- На кнопке справа должен быть бегущий человек. Удержание плавно включает
  слабую зелёную подсветку, отпускание её выключает.
- Удерживать джойстик строго вправо/влево 10 секунд: персонаж должен сделать
  несколько полных оборотов на месте, камера остаётся позади него.
- Наклонить джойстик вверх и в сторону: персонаж идёт и непрерывно поворачивает.
- Отпустить джойстик и сменить сторону: проверить плавное торможение и разгон.
- Двойным касанием джойстика присесть, повторным встать; под низким потолком
  вставание должно блокироваться стандартной проверкой CharacterMovement.
- Двигаться и удерживать кнопку бега вторым пальцем; отпускание возвращает обычную скорость.
- Дважды нажать кнопку бега во время движения: один прыжок, без зависания ускорения.
- Отпустить пальцы в разном порядке и за пределами окружностей: остановка и сброс бега.
- Свернуть и вернуть приложение во время бега: старые касания должны сброситься.
- Проверить размещение элементов на экранах разных пропорций и с вырезами.

## Статус проверки

Математика поворота проверяется отдельно от движка реальным используемым
MobileSteering.h: удержание более двух оборотов, 30/120 кадров в секунду,
плавный разгон, половинное отклонение, остановка, смена направления и пауза.
Команда из корня репозитория:

```sh
g++ -std=c++17 -Wall -Wextra -Werror -ISource/CityLiveRP Tests/MobileSteeringTest.cpp -o /tmp/citylive-steering-test
/tmp/citylive-steering-test
```

Unreal Engine и Android SDK в облачной среде отсутствуют. Сборка UE 5.8,
визуальная проверка и запуск на телефоне здесь НЕ выполнялись. Проверка исходников
и git diff --check не заменяют эти проверки. Для APK требуется отдельно настроить
совместимый с UE 5.8 Android SDK/NDK по документации установленной версии движка.
BuildAndOpen.cmd предназначен для Windows; в облачной Linux-среде он также
не запускался. Его работу и результат сборки нужно проверить на Windows.
