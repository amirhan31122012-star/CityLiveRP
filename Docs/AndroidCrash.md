# Диагностика вылета после заставки

1. На телефоне включите режим разработчика: обычно «Настройки → О телефоне»,
   несколько нажатий на «Номер сборки» или «Версия ОС/MIUI». Точные пункты
   зависят от производителя. В настройках разработчика включите «Отладка по USB».
2. Подключите телефон кабелем передачи данных, разблокируйте его и разрешите
   USB-отладку для своего компьютера. Используйте только один физический телефон.
3. Запустите CityLive RP на телефоне и дождитесь вылета. Не перезагружайте телефон:
   кольцевой журнал может потерять нужные строки.
4. В папке проекта дважды нажмите CollectAndroidCrash.cmd.
5. При успехе откроется Saved/AndroidCrash/<время>. Прикрепите AndroidCrash.txt.

Скрипт ищет platform-tools/adb.exe в ANDROID_HOME, ANDROID_SDK_ROOT, LOCALAPPDATA
(текущий SDK пользователя) и стандартном Local/Android/Sdk. Если ADB отсутствует,
установите Android SDK Platform-Tools во вкладке SDK Tools Android Studio.
Эмуляторы пропускаются. При unauthorized скрипт просит разрешение на телефоне.

Это сбор диагностики: getprop, meminfo, сведения только о пакете com.cityliverp.game,
история его завершений и crash/engine logcat. Данные и кэши игры не очищаются,
приложение не переустанавливается, телефон не перезагружается, журналы не
очищаются. Чтение exit-info доступно не на всех версиях Android; его ошибка
записывается в отчёт, остальные журналы всё равно читаются. Сведения crash-buffer
могут включать последние системные аварии — важна временная близость вылета игры.
Для причин завершения из-за памяти и native-ошибок нужен этот журнал,
а не Windows BuildAndroidV1.log, который описывает только сборку.

Скрипт проверен по структуре вызовов; выполнить Windows PowerShell/ADB на
физическом телефоне в облаке невозможно. По одному логотипу нельзя различить
нехватку RAM, ошибку шейдеров, неподдерживаемую графику или загрузку ресурсов.
